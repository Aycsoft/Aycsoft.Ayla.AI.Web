# 代码规范

本规范约束手写源码、配置和文档，不以注释数量或目录数量作为质量指标。

## 格式与命名

- UTF-8、LF、文件末尾换行；默认两空格，C# 与 Nginx 四空格。Prettier 统一单引号、无分号、100 列及尾逗号；CSS 按解析器使用分号。
- Vue 组件文件为 PascalCase，工具与状态模块为 camelCase；函数/变量为 camelCase，类型为 PascalCase，语义常量为 UPPER_SNAKE_CASE。
- Vue 文件顺序为 script、template、style；属性布局与模板缩进交由工具处理，不手工压缩多条逻辑到一行。
- 既有服务端 PascalCase 字段、端点、事件名和 CSS 选择器属于兼容契约，不能只为统一命名而破坏调用方。
- package.json、tsconfig.json、Prettier 配置禁止非法注释。依赖锁文件通过 pnpm 更新；法律声明与二进制资源保持原样。

## 分层与流程

- `api`：HTTP/SSE 传输和协议适配，不操作页面；`types`：服务契约和业务对象。
- `utils`：纯转换与窄职责浏览器适配；`stores`：跨页面状态与会话生命周期；`composables`：可复用 Vue 状态流程。
- `components`：明确输入、输出事件与显示责任；`views`：路由级装配和页面动作；不要把传输解析复制进模板。
- 先查找同类实现再抽象。仅在有真实重复或独立状态边界时抽取模块，禁止空壳转发层和万能 helpers 文件。
- 异步动作按校验、防重入、开始状态、await、错误提示、finally 清理组织；取消旧请求或防止过期结果覆盖新状态。
- 组件销毁时释放监听、Worker、对象 URL 等资源。用户取消不应被显示为服务故障。

## 注释标准

- 每个手写代码文件说明具体职责。复杂组件补充 props/emits 契约，公开转换函数说明结果和边界，测试文件说明验证目标。
- 注释解释“为何需要”和“哪里不能改”：协议兼容、权限边界、时间单位、空值语义、状态转换、流中断、资源回收。
- 不逐行翻译赋值和循环，不写无意义的“初始化”“处理数据”；不保留临时任务描述、个人工作路径和无法访问的审图引用。
- 修改代码时同步更新注释。自动注释存在性检查只是漏项提醒，不能证明解释准确或业务正确。

## 类型与安全

- 不使用 any 隐藏协议问题；外部不可信输入使用 unknown 并收窄，跨端历史兼容保留明确的回退分支。
- Markdown 的 HTML 必须经过统一安全渲染器；例外只允许在审核过的输出点单行标注。Worker 是资源隔离手段，不等于可执行任意恶意代码的强安全沙箱。
- `VITE_*` 是公开构建配置，不能存储凭据。后端负责认证和最终业务校验，前端可见状态不能替代授权。

## 样式与部署

- `styles.css` 只负责有序导入。`styles/` 按连续职责段拆分，保持历史级联顺序；新增规则应归入所属模块，避免在入口末尾继续堆叠。
- 不随意排序同名选择器、媒体查询或覆盖块；声明相同不代表在不同级联位置行为相同。
- 宿主按照服务注册、API 转发、静态资源、端点与 SPA 回退组织；SSE 必须传递取消且避免整段缓冲。
- Dockerfile 描述预构建上下文；Nginx 的代理头、缓冲与部署子路径是运行契约，发布前在目标环境执行 `nginx -t` 和真实冒烟。

## 自动验收

`pnpm check` 执行格式、ESLint（零警告）、逐文件清单与编码/职责说明、类型、单元测试、生产构建。`node scripts/check-files.mjs --write` 更新目录，不自动替代人工审查。

格式化不覆盖生成产物、锁文件、法律正文或二进制资源；C# 单独使用 dotnet format。文件清单对每个路径记录其类别与验收方式。构建成功不代表后端业务或生产部署已经通过。
