# 全项目规范化计划与验收

## 目标与边界

所有版本控制下的文件都进入验收清单。源码要求可定位职责、可理解流程、可自动检查格式；图片、视频、锁文件和法律正文按资源/生成文件验收，不伪造注释覆盖率。不修改服务端协议、真实业务数据、页面设计或发布环境，不在本次任务提交或推送 Git。

## 实施顺序

1. 基线：清点文件，确认工作区，运行现有测试与类型检查。
2. 并行审查：API/工具/类型、组件、页面/状态三个责任域逐文件审读，补齐模块职责、公共契约、复杂流程和安全边界说明。
3. 结构整理：保留外部接口，提取重复流程；全局样式按责任段拆分且保持原级联顺序；宿主入口明确代理、静态资源和路由的执行顺序。
4. 规范固化：EditorConfig、Prettier、ESLint、贡献规范与架构索引；CI 执行同一套命令。
5. 集成验收：全文件清单、格式、lint、类型、单元测试、构建、宿主编译与格式检查。运行环境可用时补充真实浏览器冒烟。

## 验收标准

- 每个手写代码文件都有具体职责说明；公共函数/类型说明语义，异步、权限、取消、恢复和兼容分支解释原因，不要求逐行翻译语法。
- Vue 文件按 script、template、style 排列；复杂脚本按状态、派生状态、事件/操作和生命周期组织。
- 不以禁用 lint、删除测试、any 强转或减少功能解决检查错误。
- `pnpm format:check`、`pnpm lint`、`pnpm check:files`、`pnpm typecheck`、`pnpm test`、`pnpm build` 全部通过。
- .NET 宿主使用 `dotnet format ... --verify-no-changes` 和 `dotnet build` 独立验收；Nginx/Docker 配置必须区分文本审查与真实部署验证。
- 文件清单明确路径、职责与验证方式；新文件必须纳入清单，不因增加目录而漏验。
- 静态检查不能替代登录、SSE、上传、历史恢复和媒体生成的真实服务验收，最终报告列明已验证与未验证项。

## 初始基线

工作区干净；23 个测试文件、73 个测试通过，TypeScript 类型检查通过。原仓库尚无自动格式与 lint 门禁，全局样式超过 6,000 行。

## 实施结果（2026-09-04）

四个责任域已完成，三个子 agent 并行改造后又交叉审查，主 agent 负责工程规范、样式、宿主与集成验收。

- 原有 API、类型、工具、测试、29 个组件、7 个页面和状态管理文件逐文件审读；补充职责、契约、兼容及资源生命周期说明。
- SSE 消费合并公共传输流程；聊天事件映射独立为 `chatEvents.ts`；个人工作区列表流程独立为 `useWorkspaceCollection.ts`，区分普通读取合并与写后强制刷新。
- 全局样式分成 12 个责任模块；拆分及格式化后均与 Git 基线比较 CSS 语法树，规则、声明和级联顺序一致。GFM 样式也通过同样比较。
- 宿主代理从入口提取为 `ApiProxyExtensions.cs`，维持 API 优先、流式传输、取消与 SPA 回退顺序。
- 修正预览旧请求回写、卸载释放、重复交互和反馈 loading；交叉审查发现的写后旧快照问题已修复并补测试。
- 把模板多语句事件移到具名函数，增加全量 37 个 Vue 模板编译回归，防止只通过类型检查却无法生产构建。
- EditorConfig、Git 换行规则、Prettier、ESLint、文件清单、贡献指南和 CI 已形成统一入口。工具链最低 Node.js 版本调整为 22.13，pnpm 保持 9.15.3。

## 未覆盖的发布验收

- 没有使用真实账号提交登录/注册、上传文件、发送付费模型请求、生成图片视频、操作个人知识/笔记/Skill 数据；这些是后续真实服务验收，不把单元测试当成业务成功证据。
- 没有在生产环境部署，没有执行 Docker 镜像运行或目标服务器 `nginx -t`；现有 Nginx 配置只完成静态审查。
- 没有宣称代码具备完整安全审计结论。Worker 限制不是强安全沙箱，正则脱敏不是穷尽式数据保护；素材公开授权仍由维护者确认。
- 未提交或推送 Git，所有实现保留在当前工作区供评审。
